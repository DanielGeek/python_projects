# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Vanilla JavaScript Tetris (HTML5 Canvas + CSS). No dependencies, no build step, no tests, no linter. Everything (README, UI strings) is in English.

## Running

Open `index.html` directly, or serve statically: `python3 -m http.server 8000` and visit `http://localhost:8000`.

## Architecture

All logic lives in a single script, [game.js](game.js), loaded by [index.html](index.html) and styled by [style.css](style.css). The script looks up DOM elements by id at load time (`board`, `next-canvas`, `hold-canvas`, `queue-canvas`, `score`, `lines`, `level`, `combo`, `energy*`, `goal*`, `overlay*`, `menu-list`, `restart-btn`, `resume-btn`, `menu-btn`, ...), so renaming ids in the HTML requires updating the constants at the top of `game.js`.

- **State** is a set of module-level `let` globals (`board`, `current`, `queue`, `held`, `score`, `lines`, `level`, `paused`, `gameOver`, `dropInterval`, ...) reset by `init()`, which is also the restart handler.
- **Board** is a 20×10 matrix of integers: `0` is empty, `1–13` index into both `PIECES` (shape matrices) and `COLORS`/`LIGHT_COLORS`. Piece type number == color index, so adding a piece means editing all three arrays (and, for a non-classic piece, the spawn rules in `randomPiece()`/`spawn()`). `POWER_BLOCK` (14) is only a shape-cell marker and never reaches the board.
- **Piece set**: types 1–7 are the classic tetrominoes (uniform, the default). Types 8–10 are pentominoes (+, U, Y; `PENTOMINO_CHANCE` 12% total), 12 is a hollow 3×3 ring (`RING_CHANCE` 3%) and 13 is the nut, a 4-block hex-like diamond with an empty center (`NUT_CHANCE` 3%); all rolled in `randomPiece()` via `pieceOfType()`. Type 11 is a single block, never random: a 4-line clear sets `singlePending` and `spawn()` makes it the next piece (a pending power-up takes priority).
- **Game loop**: `loop(ts)` is a `requestAnimationFrame` loop that accumulates elapsed time into `dropAccum` for gravity and redraws every frame. Pause/game-over stop it via `cancelAnimationFrame(animId)`. Resuming restarts it with a fresh `lastTime`.
- **Piece lifecycle**: `lockPiece()` → `merge()` → `clearLines()` (updates score/level/`dropInterval`) → `spawn()` (shifts `queue`; calls `endGame()` if the spawn position collides). `lockPiece()` also takes the undo snapshot first and runs `checkMode()` at the end.
- **Input** is one `keydown` handler using `e.code`. Rotation (`tryRotate`) is clockwise only, with simple horizontal wall kicks `[0, -1, 1, -2, 2]`.
- **Scoring**: line clears use `LINE_SCORES × level`; soft drop gives +1 per cell and hard drop +2 per cell. Level is `floor(lines / 10) + 1`, and `dropInterval = max(100, 1000 - (level-1) * 90)` ms.
- **Power-ups**: every `POWER_EVERY` (5) lines, `clearLines()` sets `powerPending`; `spawn()` then makes the *next* piece a one-block `powerUpPiece()` (shape cell `POWER_BLOCK` = 8, a `power` name from `POWER_GLYPHS`). It moves/drops like any piece, but `lockPiece()` calls `applyPower()` instead of `merge()`, so it is never stored on the board. Effects: `bomb` (3×3 around it), `bolt` (random row or column), `tint` (removes all blocks of the color it lands on; on the floor, the most common color), `gravity` (`compactColumns()`), `freeze` (`freezeLeft` = 5000 ms, counted down in `loop()` so pausing stops it; gravity is off but the player can still move/drop). Destroyed blocks give `POWER_SCORE` each. `drawBlock()` takes an optional `power` arg to draw the glyph; color is the `--power` CSS variable cached into `powerColor` by `applyTheme()`.
- **Combo / bonuses**: `lockPiece()` computes `isTSpin(current)` *before* `merge()` (T piece, last move was a rotation via `piece.rotated`, ≥3 of 4 center corners blocked), then `clearLines(tspin)` → `scoreClear(cleared, tspin)`, which replaces the old `LINE_SCORES × level` line. Points = base (`LINE_SCORES` or `TSPIN_SCORES`) × level, ×1.5 if a Tetris/T-spin-with-lines follows another (`b2b`), × `combo` (consecutive locks that cleared lines; resets on a lock with no clear), plus `PERFECT_CLEAR_BONUS` × level when the board ends empty. Plain 1–3 line clears end the B2B chain; a no-line lock does not. Power-up locks also go through this path (and reset the combo unless gravity completes a line).
- **Effects / sound**: `scoreClear()` pushes text banners (`addBanner`) and a screen flash (`startFlash`); `updateEffects(dt)` ages them in `loop()` (so pause freezes them) and `drawEffects()` paints them last in `draw()`. Color comes from the `--combo` CSS var cached in `comboColor`. Sound is WebAudio synthesis (`tone()`, `playClearSound()`), no asset files; `ensureAudio()` runs on every keydown because browsers need a gesture. `M` toggles mute, persisted in `localStorage` under `tetris-muted`. HUD shows `#combo` (`xN` when ≥2) and the `#b2b` badge.
- **Queue / Hold**: `queue` always holds ≥ `QUEUE_SIZE` upcoming pieces (`fillQueue()`); `spawn()` shifts it and pushes a pending power-up/single to the front. `holdPiece()` (C / Shift) stores a fresh `respawnCopy(current)`, swapping with `held` or spawning from the queue; `holdUsed` blocks it until `lockPiece()` resets it and dims `#hold-section` (`.locked`).
- **Modes**: `MODES` maps `modeId` → `{ name, blurb, setup?, tick?(dt), check?() → 'win'|'lose', status?(), hideBoard?, linesPerLevel?, reverseFrom? }`; `init()` reads `mode = MODES[modeId]`. Page load shows the start menu (`showStartMenu()`) instead of starting. Classic, Sprint (40 lines / 2:00), Rising garbage (`pushGarbage()` every 10 s, survive 2:00), Dig (8 pre-placed gray rows, clear all `GARBAGE` = color 14), Invisible (locked blocks not drawn until the end), Reverse (`rotationReversed()` flips rotation from level 3, level every 5 lines, reach 6). `loop()` advances `modeTime`, calls `tick`, then `checkMode()` → `winGame()` / `endGame('TIME UP')`. `status()` feeds the `#goal` HUD section.
- **Menus**: `openMenu(title, subtitle, items, cancelable)` renders numbered buttons into `#menu-list` in the overlay and stops the loop; keys 1–9 pick, Esc cancels if cancelable. `chooseMenu()` closes it, runs the item's `action`, then `afterMenu()` resumes the loop unless the action opened another menu. `showOverlay()` is the shared overlay setter (Resume / Restart / Menu buttons).
- **Energy / skills**: `energy` (0–100) gains `ENERGY_PER_LINE` per cleared line; at 100, `E` opens `openSkillMenu()`: see next 5 (`previewLeft`), swap piece (`openSwapMenu()`), slow time (`slowLeft`, gravity at half speed), undo last placement (`takeSnapshot()` / `undoPlacement()`, snapshot excludes the hard-drop bonus), extra hold (`holdUsed = false`). Skills spend all energy; timers count down in `loop()` so pausing/menus freeze them.
- **Theming**: dark is the default. Colors live in CSS custom properties in [style.css](style.css) (`:root` = dark, `:root[data-theme="light"]` = light). The `#theme-toggle` button (ids `theme-toggle`, `theme-toggle-icon`, `theme-toggle-text`) calls `applyTheme()` in `game.js`, which sets `data-theme` on `<html>`, swaps `palette` between `COLORS` and `LIGHT_COLORS`, caches the `--grid` value into `gridColor` (canvas can't read CSS), and repaints via `draw()`/`drawPreviews()` (the loop is stopped while paused/game over). The choice is persisted in `localStorage` under `tetris-theme`. The button is blurred after click so Space doesn't re-trigger it. Any new color should be a CSS variable, not a hard-coded value.
- **Rendering**: `draw()` repaints grid, board, ghost piece (via `ghostY()`, alpha 0.2) and current piece. `drawPreviews()` renders NEXT, HOLD and (while the skill is active) the queue canvas via `drawPieceGrid()`.
